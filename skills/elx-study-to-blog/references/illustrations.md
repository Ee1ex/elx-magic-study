# 为每个二级标题生成能讲清内容的图

## 先配对，再选画风

按成稿中的 `##` 逐节列出「读者的问题 → 正文支持的答案 → 图上能看见的证据」。答案具体到对象、动作、前后变化、比较项或判断条件。圈出读者应该能在图上指出来的细节，再决定用流程图、对照图、人物动作、实物局部还是分镜。每节至少一张专图，放在对应二级标题与下一二级标题之间，靠近首次讲到该关系的段落。封面、开场插画和其他章节已用的图不能替第二节占位。三级标题属于所在二级标题。

| 本节要教什么 | 画面怎么组织 | 读者应能指出什么 |
| --- | --- | --- |
| 区别或取舍 | 同一对象、同一视角并排，改变一个关键条件 | 左右哪里不同，这个差别为什么影响选择 |
| 步骤或协作 | 用相同标记跟随对象经过各步，标出人、动作与结果 | 谁先做什么，在哪一步检查或决定 |
| 分类或概念关系 | 中心问题连接具体分支，或用并列小格呈现实例 | 每一类的含义、边界和归属 |
| 人物经验或实物原理 | 让人物完成有结果的动作，或放大起作用的部件 | 看什么动作、姿态或部件能理解这段话 |
| 数据或证据 | 把指标与能回答的问题对应，有实值时保留来源和单位 | 哪种结论有依据，哪一步仍需查证 |

## 可直接填入图片模型的通用提示词

```text
这张图将放在「{本节标题}」下，给{读者}看。
读者的问题是「{一个具体问题}」。读完本节应能回答「{一句答案}」。
正文提供的依据是{两三个事实或一个真实/明确标为假设的例子}。
请画{图式}。画面中的{对象 A}正在{可见动作/状态}；
{对象 B}与它有{先后/对照/包含/条件关系}。通过{位置、标记、箭头或局部特写}让读者看见这个关系。
需要逐字准确的短标签为{必要词语，或说明无需文字}。
只使用正文支持的数量、方向、单位和结论；编辑举例画成示意，保留{最容易误读的限制}。
阅读顺序为{从哪里看到哪里}。为手机宽度简化物件、放大关键细节，颜色同时配合文字、形状或位置区分。
成功标准：遮住网页标题和图注后，读者仍能指出{是哪一个对象/哪一步/哪种差别构成答案}。
```

例如，一节讲「怎样在发货前发现少装一件」。原文约定拣货时对货号、复核时点件数。图里让同一箱货经过两名操作员，第一格放大货号比对，第二格把订单上的两件与箱内的一件并排。问读者「少装在哪一步被发现」，答案应能从第二格指出。画风和配色在这条关系确定后再选。

## 生成与验收

1. 用宿主可用的图片模型为各节分别生成，给模型可公开的必要细节。已有可用原图时也先做同样的内容配对。示意人物、产品图或分镜不充当原视频画面、实测截图或证据。
2. 逐张看实图，核对标签、数量、人物或物品身份、箭头和方向。先只看图片，用一句话复述它教会了什么，再与本节答案核对。若只能辨认出「相机」「电脑」一类名词，或图放进另一节也同样合适，调整构图或提示词后再生成。要说明动作先后，画可对照的连续帧；要定位某个时点，画能定位的观测。汇总平均值只支持整体判断。
3. 放到博客的 `public/content/`，为每张图写描述可见事实的 alt。图注解释应读出的含义或适用条件，可以标注 AI 示意。在手机正文图上检查标签、主体和关键连线。另看首页 16:9 卡片裁切；若说明标签被截断，可制作同主题、主体在安全区域的封面，正文保留完整说明图。图中的重要概念也以网页文字表达。
4. 在目标博客安装其锁定依赖后，运行 `node <本Skill目录>/scripts/check-figures.mjs <博客根目录> content/<slug>.mdx`。它复用博客的 MDX 解析器，检查每节的本地文件、alt 和重复图像内容。covered/total 表示结构覆盖；图像解码和窄屏可读性在浏览器中核对，意思是否准确要实际读图。
5. 按每节回报成图或待补原因。宿主无图片模型时可采用贴合本节的获准原图；仍缺图的章节保留为待补。用户明确要求纯文字时以该次要求为准。
