# 检索与项目参考

1. 从请求提取问题、实体、场景和时间要求。跨项目时仅读取解决问题所需的当前项目信息，不自动上传仓库。
2. status 看绑定和覆盖。首次无索引先 sync；已有索引按更新需要有界刷新，不每次全库扫描。
3. search 使用 2—3 种有意义的表达；中文支持分词与双字组合，英文保留单词。CLI 的 --query 可重复，多个表达合并排序。
4. 原始收藏和正文都可召回。检查 matchType、excerpts、fetchedAt 和 neighbors；链接邻居不是关键词命中，要说明为何进一步读取。
5. 对最相关 3—5 篇先 fetch；飞书版本、账号或权限发生变化时不能继续拿旧缓存说“最新”。用户明确同意离线查询时可 search --offline，并标明时间界限。
6. 根据正文语义、证据质量、场景适配和时效重新排序。第一版没有 embedding 模型，不把 BM25 分数称为语义置信度。
7. 不足时补关键词、沿引用读取或继续 sync；达到合理预算仍不足则报告实际覆盖和缺口。搜索无命中不等于库内绝对不存在。

回答使用项目参考模板：可复用、要调整／不适用、依据、缺口。引用真实 URL；没有真实 block ID 时不编造段落锚点。需要某个视频的原话时核对实际字幕和时间点。

知识库结论是参考；当前项目的事实优先。不能因为旧笔记写过某个方案就替用户修改代码。默认不把回答写回知识库，也不把私人关键词发送到互联网搜索。
