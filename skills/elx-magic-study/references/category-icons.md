# 分类页原生主题图标

在 Skill 新建一级／二级分类页或修改其内容之后执行。普通来源笔记、主题正文和首页不自动装饰；不在标题里加 Emoji，不修改正文来模拟图标。当前支持飞书原生选择器的“表情符号”选项，由宿主浏览器工具操作；没有已验证的 CLI 图标写入接口。

## 什么时候处理

- 创建分类后：读取实际标题和分类说明，提出一个易理解的表情图标，并在分类创建预览中说明。分类创建、正文回读成功后，再设置图标。
- 修改分类后：判断主要用途是否改变，稳定的 theme 标识保持原样。只是增加导航链接、补资料或换措辞，不换主题标识，也不随意换图标。
- 用户手动选过、来源不明的已有图标，或移除了之前的自动图标：保留。用户明确要求改它时可按当次指令手动操作，不能把普通维护当成覆盖授权。
- 无明确主题、宿主缺浏览器工具或未登录：报告待设置，不阻断已完成的正文入库。计划和图标状态不是文档写入状态。
- 只在当前调用或已授权维护中检查；不提供飞书编辑事件监听。定时维护默认只检查和提建议，不自行执行网页写入。

## 选择图标

当前 Agent 根据标题、说明和内容用途选主题；只使用实际选择器可找到的表情。建议示例：收件箱 📥、主题知识 📚、实践经验 🧪、维护记录 🛠️、知识管理 🧠、AI工具 🤖、网页设计 🎨、生活出行 🧭。这些是建议，不证明每个图标已在所有飞书客户端验证。

同层分类尽量语义清楚、风格协调，避免只为好看选无关图案。找不到目标图标可提出一个接近的备选；若改变了已经确认的含义，先告知用户。

## 网页观察 → 计划 → 设置 → 刷新回读

1. 按宿主的浏览器工具文档选取已登录会话，打开明确分类链接。核对当前页面标题与文档身份，不读取 Cookie、私有接口或内部状态。
2. 从当前可见页面读取原生图标。真正没有图标用 null；有自定义图形但不易命名，可用稳定描述（如 custom:蓝色文件夹）并保护；看不清时停止，不把“未知”当“无”。
3. 准备以下本地 JSON，运行 `icon-plan --file <文件>`。节点需已索引为 index，位于绑定根下第一／第二层；必要时有界 sync 后重试。

```json
{
  "documentId": "当前分类文档ID",
  "observation": {"url":"https://example.feishu.cn/wiki/ActualCategory","title":"主题知识","icon":null},
  "icon": "📚",
  "theme": "主题知识",
  "reason": "这个分类汇总有来源依据的主题知识"
}
```

4. 按返回 decision 处理：set 才操作网页；preserve 保留用户／未知来源选择；keep 主题未变，保持；pending 解释信息不足。plan 只更新本地任务，不会替你设置图标。已有旧的未完成操作时先重新观察当前页面，不能按旧截图盲点。
5. 执行前再次核对当前可见图标仍等于计划的 previousIcon；若变化则停止，保留他人的修改，重新观察。用原生“添加图标”或已有图标入口打开选择器，搜索文字并从实际出现的候选选择。**试点发现“添加图标”可能先立即设置一个随机图标**；打开面板也可能有副作用，须记录操作前图标，继续完成目标选择。若中途失败，记录当前可见结果及 pending 原因，不声称保持原状。
6. 选择后先观察变化，再刷新页面，核对标题／目录中的原生图标。不要因面板未关闭而重复点击。保存刷新后的截图等本机证据，供用户查看。
7. 运行 `icon-record --id <图标计划> --file <回执JSON>`。只有实际刷新核对通过才使用 verified：

```json
{
  "outcome":"verified",
  "url":"https://example.feishu.cn/wiki/ActualCategory",
  "title":"主题知识",
  "icon":"📚",
  "reloaded":true,
  "evidence":"本次截图或浏览器观察记录的本机绝对路径"
}
```

无法完成时用 `{"outcome":"pending","reason":"实际阻塞原因；若产生临时随机图标，明确记录"}`。回执命令再次核对文档身份、分类路径和正文未变；**图标值依赖宿主真实观察，脚本不会自行识别证据图片，也不把文件存在当成图标已成功的证明**。不得伪造回执。

一个分类同一时间只由一个 Agent 操作。新计划会使旧回执失效；执行网页动作前沿用当前有效计划，不让两个浏览器会话并发改图标。任何正文／标题／位置变化先停下重新观察。

## 持久化与维护

本地 library.json 的可选 categoryIcons 按文档 ID 保存自动／手动保护模式、上次成功图标和稳定主题、当前计划、状态与证据路径；icon-plans 保存具体方案和回执，不混入正文操作历史。新字段不回填旧记录。失败不会把上次自动图标覆盖为“成功”。

status／maintenance 的 pendingCategoryIcons 会列出 planned／pending 项。维护先报告，不借机改权限、重新登录到其他账号或运行未授权的 UI 写入。图标不参与正文 processedHash，不让装饰变化触发重新整理来源。

## 已验证与限制

2026-10-03 在 Edge 已登录网页上，对“主题知识”设置原生 📚 图标，刷新后仍保留，官方 CLI 复核标题和正文未变。该试点验证网页路径，状态规则另有合成测试；其他图标、自定义图形、不同客户端和界面变化不冒充已验收。选择器位置和元素编号不可硬编码，每次以当前网页为准。
