# 首次导览与场景提示

目的：用户第一次就知道书屋能做什么、哪些可选、现在需要做什么；以后只在有用的时机提醒，不每次重讲菜单。这个流程由当前Agent执行，不是脚本自动弹窗或后台监控。

## 首次调用

先运行 `onboarding`（不要求先绑定），再读取本次对话已有选择及必要的doctor／status。不把“有绑定”当成“介绍过功能”，也不因新的Skill版本号把用户偏好清空。needsIntroduction=true 时，在首次回应中展示简短导览；紧急或明确具体任务可先说明一句并执行独立步骤，避免整页介绍挡住任务。

可按下面的话改写，不原封不动输出命令：

> 我是魔法书屋的小助手，可以帮你：📥收藏并总结资料、🏷️按内容分书架、🔎在新项目中查旧经验、🗺️画知识图谱、🧹检查重复和待整理项。
>
> 还有三项可选：🌐配置外部网页／视频读取工具；⏰用你当前Agent的自动化功能定时整理；🎨新建或改名分类后，用已有界面工具设置图标。它们不是必须全部开启。
>
> 开始前我先检查运行环境，由你亲自完成必要登录或授权。已有连接会复用；没有知识库时，我会先说明并经你确认新建独立的「魔法书屋知识库」。第一次入库按内容建立必要分类，以后每次先检查分类再保存。需要 OpenCLI 时，会引导你通过 OpenCLIApp 安装 CLI 和 Agent Skills。其他可选功能以后再配。

结合实际状态补一句“现在已连接／缺少什么”，别让已绑定用户重复初始化。核心功能也有边界：收藏链接不代表读过全文，分类由Agent判断，图谱来自已索引引用，远端写入需要具体预览和授权。

## 初始化顺序

1. Node、飞书CLI和连接检查；缺工具按setup说明并询问相应安装授权。
2. 用户完成必要授权，已有位置核对后复用；没有绑定目标时按 library-bootstrap.md 完整发现同名空间，确认后建立独立「魔法书屋知识库」和首页，再绑定及首次索引。分类按首次实际资料建立，不预建大量空目录。
3. 首次导览中主动询问是否需要定时整理；已有明确拒绝／暂缓或任务则沿用。用户愿意时再问时间、时区和范围，按maintenance配置当前宿主，不预设启用。
4. 外部读取工具先介绍为可选；当前材料确实缺读取能力或用户主动要求配置时，按 reading-tools 引导。缺 OpenCLI 优先下载 OpenCLIApp，在软件内安装 CLI／Agent Skills，用户登录并核对桥接与目标读取；Agent Reach 按实际需要另行选择。只处理飞书或直接给正文无需安装。
5. 图标先说明可选，等实际新增／改名分类且有可用界面能力时再按optional-icons询问具体目标，不在首次把一批未知图标授权全部要完。

不把所有可选项堆成必须填完的问卷。问当前最相关的选择，同时继续与答案无关的工作。未回答不代表同意，也不代表拒绝，不启用任何功能。

## 本地引导记录

同一个个人状态目录内使用 `onboarding.json`（与绑定、任务回执分开），跨聊天／项目可复用。不写入远端知识库或公开仓库，不保存完整聊天、凭据或平台账号。不同个人状态目录独立；此记录仅表示该目录用户的意向，不代表当前宿主有能力或当前库已开任务。

已经展示介绍后可记录 `{"introduced":true}`。偏好只记录用户明确选择，未回答的键省略，不推断默认值。用 `onboarding-record --file <JSON>` 保存：

```json
{
  "introduced": true,
  "choices": {"schedule":"later", "icons":"never"}
}
```

可用键：readingTools（Agent Reach等读取工具）、opencli、schedule、icons、graph。

| 值 | 含义与后续行为 |
|---|---|
| ask／未记录 | 场景确实适合时可主动询问 |
| later | 用户暂缓；不按次数或下轮自动重问，等用户主动提起或明确指定的重访场景 |
| never | 用户要求不再推荐；停止主动提示，用户日后主动要求仍可办理 |
| interested | 用户有意使用；仍需核对能力、具体范围及授权，不等于已安装／已启用 |

当前用户指令优先于旧记录。用户改变选择时只更新对应键，保留其余偏好。偏好是提醒规则，不可用来取消已运行任务；任务启停按maintenance操作并验证。用户仅说“这次先不做”时尊重本次选择，不擅自记为永久never。

如果旧用户无记录，但当前对话已完整介绍过，就简短承接并记录，不再逐字重播。安装升级不重置引导文件；新功能只有与当次任务相关时简短提示，不为每个版本重新做首次引导。

## 后续场景提示

先读onboarding偏好，并核对当前能力、绑定和真实任务状态。每轮最多给一个最相关的可选建议，放在自然的任务节点，不覆盖用户当前问题；同一任务已提过不再提。没有合适场景就不提示。用户直接要求功能时进入执行流程，不再问“要不要使用”。

| 已出现的场景 | 可用能力与提示方式 | 不触发的情况 |
|---|---|---|
| 外部链接缺可用正文／字幕／评论工具 | 按 reading-tools 引导，缺 OpenCLI 时优先 OpenCLIApp | 已有工具能用；对应工具偏好 later/never；仅介绍不执行安装 |
| 新资料待入库 | 每次检查分类，必要新分类与笔记合并预览，可改位置和标签 | 不把自动分类做成每次额外开关 |
| 用户开展新项目并需要参考 | 提示可从书屋找相关方法与经验 | 不能因为Skill曾用过就扫描无关项目或全部历史 |
| 用户难以理解多篇资料的关系 | 提示可生成本地可点击知识图谱 | 用户只要一句结论、资料只有一篇、用户拒绝提醒 |
| 重复出现手动维护需求，且未开任务 | 若schedule偏好允许，提示定时检查与草稿 | 用户暂缓／拒绝、已有等效任务；不每次手动调用就推销 |
| 当前整理实际新增／改名分类 | 能力检测通过后按optional-icons询问图标 | 无能力、仅改正文、用户拒绝、无人值守任务 |
| 已完成一次真实项目实践且用户希望沉淀 | 提示可整理成实践笔记并给回写预览 | 尚未验证的设想，不冒充实践 |

这里“自动提示”指Skill被调用、当前Agent发现相关场景时的主动提醒，不是跨应用监听或后台自动执行。无人值守维护依旧只生成草稿与问题，不弹出交互式可选功能问卷、不安装工具或设置图标。核心完成结果与可选建议分开，不能把“建议过”记为“已完成”。
