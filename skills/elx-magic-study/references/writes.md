# 写入与恢复

当前脚本依照本机 lark-cli 1.0.93 的实际帮助封装；升级后命令变化先核对 help。官方内嵌文档通过 `lark-cli skills read lark-doc/...` 读取，不能把“命令不存在”当权限不足。

## 成功的证据

脚本通过 argv 传参、stdin 导入 Markdown，不经 shell 拼接。创建与更新返回后再次检查所属子树并读取正文，完整匹配预期内容；有服务端警告、partial_success、目标不一致或内容缺失时视为未核实。

精确替换检查原文唯一匹配、基线 hash 和回读后的预期全文。追加保留既有内容。revision 参数会传给支持的 CLI，但不把它宣称为跨设备原子事务保证。

## 请求超时或中断

plans／plan-show 检查步骤：pending 可按已确认计划执行；sending、unknown、needs_review 不能重发。

先用 `diagnose --id <计划> --step <序号> [--doc <结果链接>]` 做只读诊断。它返回核验结果、长度／摘要比较和各最多 160 字的开头摘录，不改变计划状态；摘录不是准确缺失位置，不据此自动放宽匹配。普通错误记录只保存比较数据，不保存正文。

创建结果未知：在**已授权写入根**中查找标题和该步骤独有的 ELX记录 标识，读取候选正文确认。没有找到不能立刻认定未创建，因为搜索索引可能延迟。保留未知状态，请用户或后续在线查询查证。

确认目标链接后执行 recover。recover 只读取并核对标识和完整内容，不发送第二次写请求。核实成功后，原计划剩余 pending 步骤才可继续；已验证步骤会跳过。

服务端警告或部分成功不能仅靠 recover 忽略。先依据当前内容和官方返回解释问题，准备有明确目标的修复方案；原操作记录保留为待核实，不能篡改 JSON 伪装完成。

## 取消和替代未执行计划

用户明确取消时，`plan-cancel --id <计划> --approve <原digest> --reason <原因>` 只标记本地终态并保留历史。改用新方案时，`plan-supersede --id <旧计划> --replacement <同库新预览> --approve <旧digest> --reason <原因>` 记录替代指向；新计划仍需自己的授权摘要。

只接受全部步骤尚未发送的计划。已完成、已发送或结果未知的计划不能以取消掩盖影响。终态无法 apply／recover，maintenance 不把它们作为活动待办；plans 仍可追溯。

## 不自动回滚删除

部分成功时给出已经创建／更新的文档链接和未完成步骤。不为“撤销失败”自动删除文档或还原用户新增内容。需要恢复时列明准确对象、变化和影响，由用户决定。
