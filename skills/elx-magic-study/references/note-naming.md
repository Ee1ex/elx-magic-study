# 入库标题与首页说明

## 新笔记标题

新收录的来源笔记用「具体内容概括丨末级分类名称」。概括优先约8字，最多10字符，中文、字母、数字、内部空格均计入；脚本按NFKC规范后Unicode码点计数。不是越短越好：优先保留品牌／产品／方法对象和要点，例如「OPPO耳机耳帽选购」（10字符），不简化成失去对象的「耳帽选购」。内容确实简单可少于8字，不凑字数、不截断重要型号或捏造品牌。

- 后缀取实际归档路径最后一级名称，不用技术类型source，也不写整个路径。
- 不加“来源笔记：”“文章总结：”等惯用前缀；原始完整标题、作者和来源链接放正文。
- 新建source动作提供 `titleSummary`（概括）和 `classification`，省略title。plan解析现有或前序新分类后生成完整title和正文首个一级标题。若同时提供title，必须与生成值一致，不允许伪造后缀。
- 返回的title、正文首标题与分类一起预览，用户调整后重建计划。重名应核对来源，避免重复；确需区分时重新概括对象或角度，仍不超过10字符，不盲目追加编号。
- 仅有链接时不能假称内容总结；用已确认的原始标题／用户指定信息拟保守概括，coverage与classification保持pending，无充分信息先询问。
- 首页、分类文档不套此格式。旧计划无titleSummary仍兼容，旧笔记不会自动重命名；只有用户明确指定对象和新标题时才用官方改名操作，核对位置、原文和链接不变。正文首标题如需同步，只改对应标题块。

示例：`{"kind":"create","category":"source","titleSummary":"LLM知识库方法","parent":"实际分类Wiki链接","content":"含原始标题、作者与来源的正文","classification":{"...":"实际核对的分类协议"}}`。示例占位信息不能直接执行，完整分类协议见 classification.md。

## 新知识库首页

按 [首页模板](../assets/templates/library-home.md) 填写真实知识库名称、介绍和用途，随后放功能说明、可复制提示词、可选能力与确认流程，最后接实际导航。首次首页的完整正文必须进入初始化预览；用户确认后创建、填充并回读，不能只建一个空“书屋首页”就算初始化完成。

首页模板中的知识库名称是正文大标题；已有首页的文档标题、空间名称不因模板自动改名。当前功能和计划中的愿景分开，不把可选能力标成已启用。不生成空目录或虚构导航链接。

新建空首页在取得真实链接并绑定后，用现有plan的append/index动作填入已预览的模板内容，再apply回读；如果与初始化属于同一明确授权，无需重复确认同一正文范围。已存在的首页先读取正文与块结构：保留导航／历史／资源，只有获准的占位介绍区域可用官方block_replace替换；不能整篇overwrite。历史版本说明保留并注明历史，不当作当前指南。

再次初始化时先检查同一介绍与指南是否已存在；不重复追加说明书。结果未知先回读与查证，不靠重发补齐。完整流程见 library-bootstrap.md。
