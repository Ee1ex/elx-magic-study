# 收藏、整理与回写

## 区分三种请求

- “先收藏”：保存真实链接、标题和备注，不强制阅读全文。
- “总结”：仅按本次目标给结果；没有入库意图不写库。
- “整理入库”：读取内容、查已有主题、给增改预览，再按授权保存。

## 来源获取

复用宿主已可用的网页、字幕和文件工具。没有适用工具时先读 [reading-tools.md](reading-tools.md)：缺 OpenCLI 优先引导 OpenCLIApp 内安装 CLI 和 Agent Skills，再核对桥接与目标试读；Agent Reach 按平台需要另行选择。用户拒绝可只存链接或提供正文。B站可通过 Agent Reach 的 bili/OpenCLI 路由获取；仅网页简介不算视频内容。字幕缺失时可登记待处理；需要转写服务、付款或外传资料时先说明并确认。图片、图表和操作画面不能由字幕臆测。

首次外部来源用 capture 登记。获取正文后用 source-content 记录覆盖范围和来源方式。已有飞书文档通过 sync/fetch 读取，不把原文重写成摘要。

## 整理步骤

1. 读足够材料，核对正文是否截断。记录来源日期、获取时间与信息缺口。
2. search 查找已存在的来源和主题，fetch 核对正文；多个教程引用同一原始作者时保留来源链。
3. 每次新来源按 [classification.md](classification.md) 检查当前分类，优先复用；首次空库也按内容创建必要分类，以 shelf 与 parentStep 将分类和笔记并入同一计划。基于正文选择少量标签和已有主题，只有链接时待整理，用户指定优先。用来源模板归纳重点、适用条件和证据；推断单独标注。
4. 优先补充已有主题，避免为每个词新建页面。实践回写记录环境、验证过程和结果。
5. plans 查已有同来源版本的草稿／完成记录，避免重复生成。sourceIds 必须绑定本轮实际使用的来源版本。
6. 新建来源动作按 [note-naming.md](note-naming.md) 提供titleSummary与classification，省略title：内容概括优先约8字、最多10字符，保留品牌／对象等细节；脚本生成「概括丨末级分类」并同步正文首标题，原始完整标题留正文。展示plan返回的完整标题、分类路径、标签、关联主题、理由、覆盖与正文要点；新分类同时展示名称和用途，不捏造URL。修改后重建预览，不沿用旧digest；主题改写另列计划。
7. 用户确认后调用 apply，核对回执。失败转 writes.md；不能绕过未知状态重建同名页。
8. 分类与笔记父子依赖由同一计划 parentStep 解析真实结果，一次确认后连续完成；不因此再问一次。额外补充首页导航或主题正文仍须先取得真实 URL 并展示独立增改范围，不能借分类扩大授权。

## 结果质量

来源笔记保留出处；主题页连接多个来源；项目参考解释当前适用性。不要把原文、摘要、AI 结论当成三份独立证据。冲突不能确定时并列保留。知识不是越多越好，没形成可复用内容的资料可以留在收件箱。

## 收藏的保存回执

capture 后先说“已生成本地收藏记录”。用户明确要求存飞书且绑定位置唯一时，可准备并展示单条来源页计划，再根据已经明确的单条写入授权执行，不必重复问无实质变化的问题。涉及主题改写或新增其他页面需相应范围授权。

只在 apply／recover 回读成功后说“已保存到飞书”并附实际链接。不要把本地 JSON 路径当飞书链接。

## 给图谱留下短说明

准备计划时，为来源／主题页的 action 可附 summary：用 1—400 字符讲清“讲什么、何时有用、有哪些依据或限制”。摘要描述修改后的整篇知识页；追加时需先阅读全文，不能只把新增段落当整篇摘要。不确定就省略，图谱会显示正文摘录。摘要进入同一预览，写后绑定核验的正文版本；不单独修改远端正文。

## 新增／改名分类后的可选步骤

本轮分类页创建或经独立授权的分类改名已实际成功时，按 [optional-icons.md](optional-icons.md) 检测当前宿主是否具备可用的Computer Use或浏览器操控能力。具备时展示真实目标和图标建议，询问是否优化；同意后才操作飞书原生图标。新建普通来源笔记或仅追加分类正文不触发，无能力不阻断整理，不为图标安装工具。
