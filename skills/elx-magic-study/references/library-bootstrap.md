# 专用 Wiki 知识库初始化

飞书用户授权通过、尚未绑定目标时读取。默认独立空间名固定为「魔法书屋知识库」；只影响首次新建，不自动改名或迁移任何已有库。目录按library-organization.md组织：首页下直接建立需要的内容主题；不预建“收件箱与来源”“主题知识”“实践经验”。“待整理”和“书屋管理”仅有实际需求时创建。Agent 使用官方 CLI 完成初始化，`space-discover` 只做发现，不创建空间。

## 先发现再决定

1. 已有绑定优先运行 status 并核对账号及目标可读性，不因为名称不同再建库。用户明确给出已有目标时，核对后走 setup 的绑定流程。
2. 没有明确目标时运行 `node <SKILL_ROOT>/scripts/library.mjs space-discover`，有指定 profile 全程保持一致。它不要求已有绑定，不写本地状态或飞书；完整分页后才返回建议。
3. `already-bound`：沿用绑定；`confirm-reuse`：展示唯一同名空间，确认目标与读写范围；`choose-space`：展示多个同名候选，由用户选择，不能只凭名称自动绑定。
4. `confirm-create`：仅表示当前账号可见空间中没有同名项。说明这一范围；若用户知道已有空间，先处理可见性，不另建替代品。`incomplete`、权限错误、无效响应或分页失败不能当成“没有知识库”。达到发现预算时让用户提供明确目标或按官方 CLI 继续只读核对，不无限扫描。

## 初始化预览与确认

新增专用库时把 [workbench.md](workbench.md) 的三篇管理页与一张Base表纳入同一次完整初始化预览，说明后续自动更新区域和用户填写区。确认后按官方CLI创建并绑定；已有库不自动覆盖或重复创建同名管理资源。

没有既有目标时说明：

> 将新建一个独立的飞书 Wiki 空间「魔法书屋知识库」，建立「书屋首页」作为读取与写入根。书屋管理下会放“书屋状态总览”“个人整理偏好”“主题更新建议”和多维表格“书屋工作台”，用来审阅预览、填写偏好和查看异常；后续仅指定自动区域和机器字段随整理更新。内容分类等第一份资料整理时按正文创建。确认完整预览后，我会完成创建、回读和绑定。

预览包含空间名、用途、首页标题、同一用户身份、绑定范围及[首页模板](../assets/templates/library-home.md)生成的完整正文：最前面是知识库大标题、介绍和用途，下面才是功能说明和提示词，末尾是实际导航。用户一次确认此具体范围后执行，不在创建空间和首页之间重复问同一件事。需要新增账号权限仍按 setup 单独说明确认。空间默认权限如不符合用户要求，应报告，不自动修改成员或分享设置。

## 官方 CLI 执行与回读

先读取当前 `lark-cli skills read lark-shared`、`lark-cli skills read lark-wiki` 和相关命令 help；以下是已核对的命令形状，不把占位符直接执行。

```text
lark-cli wiki +space-create --name "魔法书屋知识库" --description "保存魔法书屋整理与收藏的资料" --as user
lark-cli wiki +node-list --space-id <真实space_id> --as user
lark-cli wiki +node-create --space-id <真实space_id> --title "书屋首页" --obj-type docx --as user
```

- 创建前在个人状态目录（不是仓库）保存本次初始化记录 `bootstrap-<唯一编号>.json`：已确认范围、账号摘要、执行阶段、每步 sending／verified／unknown、真实结果 ID。发送前保存 sending，响应后立即保存回执；不含凭据。恢复时先检查这个记录，不新起同名初始化覆盖历史。
- `+space-create` 返回 space_id，可能没有 URL。用官方空间详情／列表回读名称、描述和 ID，不能捏造空间链接。新建后先列顶层节点，复用已存在且用途合适的首页；多候选需核对，只有确认缺少时创建已批准的首页。
- 必须显式传真实space_id，不能省略后意外落入my_library。首页创建返回node_token、obj_token等；先用node-get核对空间并fetch正文。正文缺URL时运行 `node <SKILL_ROOT>/scripts/library.mjs resolve-url --doc <实际返回的obj_token>`，只读查询官方Drive元数据with_url并核对身份、类型和链接。缺必要元数据权限时按setup说明并确认增量授权；不猜域名、不重复创建。必要时仅从核验链接的真实域名与返回的node_token组成Wiki链接，再node-get确认。
- 首页已经存在时不覆盖正文。展示并核对首页真实链接，将该 Wiki 节点子树作为 readRoot/writeRoot 执行 bind（范围必须包含在原确认中）。本 Skill 当前不是整个空间永久自动发现，用户在首页外新建顶层节点不会自动纳入授权。
- `bind` 使用可用的新本地编号、name「魔法书屋知识库」及真实首页链接，不覆盖已有编号。新建空首页随后以plan的append/index动作写入已确认的介绍和说明书，回读核对大标题、用途、功能及提示词；不只创建空页。已有首页不重复追加或覆盖，按 [note-naming.md](note-naming.md) 保留用户内容。最后少量sync，报告绑定与覆盖结果；空间创建、首页填充、本地绑定和全文同步分别核验。

## 中断与恢复

创建空间／首页超时或回执不完整时标 unknown，停止后续写入。先以已返回 ID、创建前候选、名称／描述、所属空间和真实节点回读查证；只有名称相同不足以认领未知结果。同名多个对象或无法确定时让用户选择或稍后查证，不能盲目重发，也不自动删除“多余”空间。

空间已确认创建但首页未完成时，只恢复首页步骤；首页已存在但绑定未完成时，只恢复核对和绑定。明确没有发送的步骤可在原范围内继续。记录和真实对象均保留，不自动回滚删除。

## 第一次与后续入库

### 新首页完成标准

所有通过本 Skill 新建的专用知识库首页，必须使用 [library-home.md](../assets/templates/library-home.md) 的当前版式，不另行生成纯文字长篇说明或只保留飞书默认占位模板。替换真实库名后依次包含：知识库大标题与简短介绍、三步使用流程表、“功能＋可复制提示词”速查表、命名示例、可选配置短列表和保存流程说明；功能说明与当前实现一致。

首页填充后读取正文及结构核验：流程和功能表确实形成表格块，功能表覆盖当前模板全部常用场景，库名正确，无未替换占位符。只建好空间／空首页、只生成本地草稿、把表格写成普通段落，都不能报告首页初始化完成。新空间尚无资料时不虚构导航；后续真实链接再按授权补充。

已有首页继续保留用户内容；无明确更新授权不套模板覆盖。相同说明已存在时复用，不重复追加。若回读发现缺项，沿本次已确认初始化范围补齐并核验；结果未知先查证，不重新创建空间或首页。

绑定完成不代表分类已经建立。每次新资料入库都读 classification-context，优先复用已有用途合适的分类。空库第一次也按正文决定必要分类；仅链接或材料不足可以按需建立「待整理」一级暂存位置并标 pending，不凭标题推断主题。

新分类使用 `category:shelf`，正文说明用途和收录范围；笔记用 `parentStep` 指向同一计划中前序分类步骤。完整分类树、理由与笔记要点放在同一预览；一次确认后 apply 自动依次创建、回读、解析真实父节点再入库。详见 classification.md。不得借第一次初始化授权任意新增之后未预览的分类。
