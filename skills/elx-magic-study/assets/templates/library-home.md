# {{知识库名称}}

这里保存通过魔法书屋整理的文章、视频、评论和实践经验。把值得留下的资料变成有来源、能检索、可复用的知识，供后续学习与项目参考。

## 这个知识库怎么用

先收藏与整理，再带着问题回来检索；在实际项目中验证过的方法，可以继续补成实践笔记。每份资料记录出处、核心内容、适用条件和实际读取范围，并区分原文观点、个人经验与 AI 推断。

## 魔法书屋使用说明

在能识别 `elx-magic-study` 的 AI Agent 对话中提出需求。飞书负责保存正文，你仍可以直接阅读和编辑；Skill 负责引导 Agent 整理、核对和写入。

### 收藏与总结

「用魔法书屋整理这个链接，保留来源，说明读到了哪些内容，先给分类和入库预览。」

可处理文章、已有飞书文档，以及外部工具实际取得的视频字幕和评论。只想留链接时说「先收藏，正文以后补」；只要求总结时不会主动入库。

### 分类与命名

「按内容选择已有分类，列出标签和关联主题；没有合适分类时，把新分类一起放进预览。」

笔记标题采用「具体内容概括丨末级分类」。概括以约8字为目标，最多10字符，优先保留品牌、产品、方法或核心对象。例如「OPPO耳机耳帽选购丨数码与音频」。来源原始标题、作者及链接保留在正文。

### 查找已有知识

「在知识库里找与『我的问题』相关的资料，给出依据，并说明适用条件和仍缺少什么。」

重要结论会回到原文核对；没有找到会说明覆盖范围，不把没有命中当成库内绝对不存在。

### 为当前项目提供参考

「结合当前项目，从知识库挑出可复用的方法、经验和需要避开的坑。」

换项目使用需要当前 Agent 能识别 Skill 并访问同一知识库；历史笔记是参考，当前项目事实优先。

### 保存实践经验

「把这次已经验证的做法整理成实践笔记，写清环境、结果和限制，先给保存预览。」

尚未验证的想法不当作实践结果，更新相关主题的范围会单独说明。

### 查看知识图谱

「为当前知识库生成一个可以点击查看来源的知识图谱。」

图谱按需生成本地 HTML，展示已索引资料的引用关系；不代表全网知识或自动推断的因果关系。

### 检查与维护

「检查待整理资料、重复来源、缺少正文和需要复核的问题，先不要修改。」

可先手动检查。定时维护需要宿主支持并实际注册，默认只做检查和待确认草稿，不自动改写远端笔记。

## 可选能力与前置条件

- 核心环境：支持 Skill 和本地命令的 Agent、Node.js 22+、官方飞书 CLI 及你本人授权。
- 外部平台读取：先检查已有工具；缺 OpenCLI 时可引导安装 OpenCLIApp，在应用内安装 CLI 和 Agent Skills，再检查浏览器扩展及本人登录状态。Agent Reach 按其他读取需求另行选择，不是必装前置。
- 分类图标：「检查本次新增分类能否设置合适图标，先给建议。」需要当前宿主实际具备界面操作能力，经你同意才修改。
- 定时维护：「引导我设置每周检查，先确认时间、时区和范围。」有兴趣不等于任务已启用；拒绝或暂缓不影响普通整理。
- 密码、Cookie 和密钥不需要粘贴到聊天中。需要额外安装或新增权限时，先说明范围再确认。

## 保存前后会发生什么

先阅读与检查现有分类 → 展示分类、标题、正文及读取范围 → 你确认或调整 → 连续完成已确认的写入 → 回读核验并提供真实链接。

只有本地草稿时不会说已保存到飞书；仅链接、部分评论或字幕会明确标注，未读取的图片和视频画面不会补猜。失败或结果未知先查证，不重复建页。删除、迁移、改权限不属于普通整理。
