# REQ-009 新资料自动分类入库

日期：2026-10-03。用户已确认：新资料自动分类、少量标签、匹配已有主题、分类预览可修改。LEVEL 1，当前 Agent 负责语义判断，不接外部分类模型。

## 使用结果

提供文章／视频正文后，小助手先读授权范围内已有书架，再推荐一个主位置、0—5 个标签、0—3 个已有主题及其依据。生成一份包含目标、理由和正文的预览，确认后按原计划机制写入。没有正文时留待整理；用户指定的位置优先。

## 最小实现

1. classification-context 只读输出授权写入根下两层节点、已有标签、基于关键词的主题候选与来源版本／覆盖；候选不是已确认分类，Agent 阅读后判断。目录有界且明确不完整状态，不能据局部结果认定某分类不存在。
2. plan 的新建 source 动作可带 classification：来源版本、状态、判断依据、理由、标签、主题证据、新分类建议。父节点使用已有真实 URL；脚本核对两层路径及来源／主题版本。老计划保持可用。
3. 标签和已核对的主题链接附到来源笔记中，分类元数据保留到本地索引；仅建立来源到主题的引用，不顺带修改主题正文。
4. 用户修改分类时重建预览和 digest，按现有 plan-supersede 保留旧计划；原授权不能用于新计划。新分类只提出建议，不自动创建。

## 验收

- 正文充分时，主分类／标签／主题依据完整进入预览及实际合成写入，只有一个来源笔记；能通过标签查询和引用关系找到。
- 仅链接默认 pending，无内容标签或猜测关联；用户明确指定已有位置可保留，但不假装读过正文。
- 标签去空、规范同形同大小写写法，最多 5 个；主题最多 3 个，必须提供来源与主题的原文依据。
- 目录不完整、重复游标、越界／过深路径、不存在主题、来源更新、关联主题更新、分类路径移动均有明确停止／降级行为。
- 修改预览需要新 digest，原文／已完成计划及未知写入保持既有边界；旧版无 classification 的计划回归通过。
- 不修改真实知识库、不把关键词检索测试当语义分类准确率；真实分类质量和飞书显示单独待验证。
