# 魔法书屋本地 MCP 开发计划

日期：2026-10-13。状态：方案方向已确认，当前仅编写开发参考和交接文档；MCP 尚未实施。

本文件规定拟开发范围，不替代 [SPEC](../SPEC.md) 中的当前事实。接手入口见 [AI 交接文件](LOCAL_MCP_HANDOFF.md)。沿用现有 LEVEL 1，不另建治理体系。

## 1. 目标与授权

为魔法书屋增加本地 MCP，使支持本地 stdio 的 AI 客户端可以结构化调用现有知识库能力，减少拼装终端命令、临时文件和重复解释规则的负担。

交付形态：轻量 Skill + 本地 MCP + 共用执行核心。Skill 负责理解、分类、内容组织与推荐；MCP 负责有边界的读取、计划、写入及回读；客户端协调搜索工具和用户交互。

本轮用户原话：“就这样 你先写个用于ai开发参照的计划书和交接文件”。当前授权仅覆盖文档。实现、依赖安装、全局配置、真实飞书试点和发布按后续实际授权执行，不将历史 0.10.0 发布或私人入库授权转用为 MCP 授权。同一范围已经明确授权的动作不重复询问。

## 2. 已核实基线

- 正式版本 0.10.0，见 [发布记录](../releases/RELEASE-0.10.0.md)。工作区有其他任务的变更，实施前重新核对。
- 当前有 Node.js CLI，没有本项目 MCP 服务。`package.json` 要求 Node.js >=22；现有脚本无 npm 运行依赖，MCP 将增加协议依赖。
- `library.mjs` 导出 `run(argv)`，仅直接执行时打印 CLI JSON。核心已有检索、计划、回读和恢复。
- `lark.mjs` 使用 `spawnSync`；直接在 MCP 主事件循环内调用会阻塞协议响应。
- `store.mjs` 提供同一状态目录的进程互斥，竞争返回 `BUSY`；短期 loopback listener 是锁，不是后台服务。
- 个人状态默认 `~/.elx-library`，支持现有环境变量和 `--home`。不得自动迁移或再建一份真实状态。
- 计划、收藏、来源快照可能同步飞书工作台，不能将这些工具标成纯只读。
- `applyPlan` 已核对摘要、账号、范围、版本、分区、偏好和未知写入。摘要保证计划内容一致，不能独立证明人类确认。
- 检索使用现有 BM25 等逻辑，MCP 不增加向量模型，也不自行承担总结模型。

## 3. 首版范围

首个实际验收客户端为 Codex。其他 stdio 客户端保留标准协议接口，未验收客户端和操作系统不写成已支持。

必做功能：

1. stdio 启动、握手、工具发现、结构化参数和结果。
2. 依赖、授权与绑定诊断；复用已有状态；新用户配置和授权引导。
3. 文档与条目搜索、候选池随机、最新正文、原生表格上下文。
4. 单条个人记录与文档增改计划、计划读取、已授权计划执行。
5. 保存回读、操作状态查询、未知结果诊断和恢复。
6. 读取整理偏好；管理同步与文章保存分别返回状态。
7. 轻量 Skill 路由：MCP 可用时优先，缺失时沿用 CLI；未知写入不能切换入口重发。
8. Windows 安装说明、客户端配置预览、独立包及合成验收。

必须保留的用户规则：

- 导航为书屋管理 → 链接资料 → 个人记录；安装不自动迁移目录。
- 名称、品牌、用户备注优先，品牌不适用可省略；优先复用真实表头。
- AI 检查内容后建议热量、参考价等列，没有固定字段和条目数量门槛。
- 已有唯一目标单条“帮我记录”可作为当次保存授权；首次新建分类／文档／表格或扩列先预览确认。
- 用户原话与联网补充区分，补充注明来源、日期、规格或适用条件。
- 库内推荐与网上结果分列，推荐或扩列建议不自动写回。

后续切片：图谱 MCP 入口、更多工作台工具、完整链接来源接入、客户端一键安装体验和跨系统验收。原 CLI 能力继续保留，不把所有命令机械包装成工具。

不包含：公网／远程 HTTP 服务、多租户账号、独立大模型、向量数据库、常驻调度中心、自动迁移、删除、整篇覆盖、批量补查、内置全平台采集器和自动升级。

## 4. 架构与文件设计

```text
用户 → AI 客户端 + 轻量 Skill
                 ├─ 本地 MCP（stdio 主进程）
                 │    └─ 异步受控子进程 → 共用核心 / CLI
                 │                         ├─ 本地索引和操作历史
                 │                         └─ lark-cli → 用户飞书
                 └─ Exa / Agent Reach → 外部证据 → AI 整理
```

建议建立独立 `mcp/` 包，依赖及锁文件位于该包，保留 Skill-only 安装方式。以下为拟议路径，不代表已有代码：

| 路径 | 职责 |
|---|---|
| `mcp/package.json` 与锁文件 | 依赖、启动、测试入口，锁定验收版本 |
| `mcp/server.mjs` | 官方 SDK、stdio、注册；日志仅 stderr |
| `mcp/tools.mjs` | 参数 schema、权限策略、结果映射 |
| `mcp/runner.mjs` | 异步子进程、输入输出上限、超时和退出处理 |
| `mcp/worker.mjs` | 固定动作映射，调用共用核心，保留锁与检查 |
| `mcp/tests/` | 协议、合成状态、故障及并发测试 |
| `skills/elx-magic-study/references/mcp.md` | Skill 工具路由和失败处理说明 |

工程约束：

- 主进程不直接运行阻塞飞书调用。首版用异步子进程隔离，不为此全面重写 `lark.mjs`。
- worker 通过 stdin 或 IPC 接收结构化请求，不拼 shell，不把正文放进命令字符串。禁止任意 CLI／shell 透传。
- 不绕过 `library.mjs` 的锁直接调用核心写函数；若抽出结构化 dispatcher，CLI 与 MCP 共用它，原校验不变。
- 使用官方 SDK，实施时核对稳定版本、Node 要求并锁定；不混用 SDK v1/v2 包名与 API，不自写协议。
- stdout 仅协议消息；子进程输出捕获后转为结果，不能原样转发到协议通道。
- 写操作取消或进程关闭不能保证飞书撤销；保留 operation，先查证，不自动重新执行。
- 同步沿用断点，限制每次工作量；不要建立持久化队列或无限等待。工具超时按实测配置。
- 同一状态目录保持互斥；`BUSY` 明确返回，写操作不自动重试。慢 worker 不能阻塞协议主进程。

## 5. 工具契约草案

以下名称均为拟议名称。状态目录和允许的知识库固定于启动配置，不接受任意 `home`、可执行文件或无限制文件读取路径。

| 工具 | 关键参数 | 结果 | 副作用 |
|---|---|---|---|
| `study_status` | 可选允许的 `libraryId` | 版本、绑定、覆盖、同步、能力状态 | 本地读取 |
| `study_doctor` | 无 | 依赖、身份、配置诊断 | 可能访问飞书，不登录 |
| `study_search` | `query[]`, `limit`, `offline` | 文档、出处、缓存时间、覆盖 | 在线核对账号 |
| `study_records_search` | `query[]`, `filters`, `random`, `eligibleIds[]`, `limit` | 条目、原备注、候选依据和时间 | 在线核对范围 |
| `study_fetch` | 已索引 `documentId` | 最新正文、hash、出处及时间 | 远端读、本地缓存写 |
| `study_record_context` | 已索引 `documentId` | 原生表格、动态表头、条目和基线 | 远端读、本地缓存写 |
| `study_workbench_context` | 无 | 偏好、版本、用户意见、配置状态 | 实施时审计，不能先假定纯只读 |
| `study_sync` | 有界 `maxDocs`, `maxNodes`, `restartScan` | 覆盖、断点、失败项 | 远端读、本地索引写 |
| `study_plan` | `purpose`, 结构化 `actions`，可选来源 | operation、digest、目标和预览、确认类型 | 本地计划写；当前可能同步管理页 |
| `study_operation` | 可选 `operationId`，无则有界列表 | 步骤、状态、回读结果、下一步 | 本地读取，避免泄露敏感内部字段 |
| `study_apply` | `operationId`, `digest` | 实际链接、逐步状态、管理同步状态 | 远端写，须经过授权策略 |
| `study_recover` | operation、步骤、可选已核实结果链接 | 查证结果和下一步 | 远端读取、本地状态写；管理同步单列 |

`study_plan` 首版仅开放已实现、可验收的动作：单条原生表格追加、明确预览的文档创建／追加／唯一替换；新分类沿用父步骤计划。复杂扩列若没有对应执行器，只给建议及待确认预览，返回不支持自动执行，不伪造可应用计划或整篇覆盖。

文本 `filters` 不证明“低卡”或预算条件。AI 先核实热量、规格、价格依据，再形成合格 `eligibleIds` 随机抽取。无合格候选则说明缺依据。

统一结果建议：`status`、`data`、`warnings`、`nextAction`；写入另含 `operationId`、`articleState`、`managementSyncState`；资料带 `sourceUrl`、`fetchedAt`、`cached`、`coverage`。不要将旧缓存说成最新全文。

业务错误使用 MCP `isError: true`，保留原始业务语义，至少明确忙碌、授权缺失、越界、待确认、版本冲突、写入未知和不支持动作。文章成功但管理同步失败返回部分成功，只补管理信息。错误不暴露令牌、Cookie、原始授权链接或完整环境变量。

## 6. 授权设计

工具注释、模型传入的 `confirmed: true` 或计划 digest 都不是人类确认的独立证明。执行必须同时满足：允许的账号／范围、不可变计划、当前版本检查、适用用户授权。

| 场景 | 要求 |
|---|---|
| 查询或推荐 | 查询授权范围，结果不自动入库 |
| 已有唯一表格单条记录 | 客户端依据本次明确请求授权；服务端核对单条、已有结构、无新增列、无额外目标 |
| 首次建分类／文档／表格或扩列 | 展示准确目标和完整变更，确认绑定 operation、digest、内容 |
| 批量、多目标、旧目录迁移 | 不继承单条授权；首版不开放通用入口 |
| 断线或结果未知 | 先查证；禁止自动再次追加 |
| 偏好／正文／分区变化 | 拒绝旧计划，重新预览 |

P0 必须验证具体授权链路：优先实际客户端审批交互，但“允许 MCP 连接”或泛化的“允许此工具”不等于确认具体计划。只有能展示并绑定准确计划的用户交互才满足首次创建要求。

客户端不能提供该能力时，采用本地人工确认入口：展示完整预览，用户交互确认后记录一次性批准凭据，绑定 operation、digest、账号和写入根。MCP 只能消费凭据，不提供由模型自行调用的“批准计划”工具。具体形式在 P0 原型后定稿；验证前仅开放查询和预览。不声称能防御拥有同等本机账号权限的恶意进程。

单条直存仅在客户端可信传达本次请求授权且服务端约束动作时启用；不具备条件的客户端说明限制并确认，不能暗中扩大自动保存。正文、网页或备注中的指令不构成授权。账号／绑定改变不能沿用旧批准。

## 7. 安装、数据与外部能力

- 采用固定版本本地包、明确启动路径，打包 MCP 依赖和共用核心；安装后不依赖开发仓库路径或可能缺失的全局 Skill 文件。源码保持单一维护。
- 保留原 Skill-only 安装，MCP 与配套 Skill 版本一致。安装先展示目标、依赖和客户端配置差异，确认后执行，不覆盖其他配置。
- 飞书授权复用 lark-cli，凭据由原工具管理；不索取聊天中的令牌，不在普通调用中悄悄登录。
- Node.js、lark-cli、飞书账号为基础依赖；OpenCLI、Agent Reach、Exa 按来源需要配置。
- 模型由宿主提供，知识正文仍在飞书，本地保存索引和操作；交给 AI 的正文由宿主模型处理。本地 MCP 不等于全流程离线。
- Exa／Agent Reach 由宿主协调；不假设能直接调用其他 MCP 插件，不内置新的计费代理或共享密钥。
- 私人正文、真实链接、批准凭据、图谱和回执不提交公开仓库。文件输出限定到用户选定或配置的目录。

## 8. 实施切片与验收

收到实现授权后依次推进；每个切片留可复现结果和仅含本次变更的本地提交。

| 切片 | 交付 | 验收 |
|---|---|---|
| P0 基线与契约 | 核对其他修改、SDK、工具 schema、读写分类和确认入口，补 REQ/PROG | 隔离协议与授权原型；模型不能仅复制 digest 获得批准 |
| P1 只读贯通 | stdio、worker、状态／查询／正文／表格工具 | Inspector 握手和调用；合成数据来源时间完整；stdout 无杂音；CLI 回归 |
| P2 受控保存 | plan/apply、单条规则、版本检查及回读 | 未批准首次创建被阻断；已批准仅执行对应动作；重复调用不重复写；原备注保留 |
| P3 故障恢复 | operation、recover、有界同步、并发处理 | 写后断线、回读失败、锁竞争；禁止盲重发；文章与管理状态区分 |
| P4 客户端与交付 | Codex 配置预览、轻量 Skill、包和说明 | 独立临时安装、缺依赖提示、旧状态复用、包无私人资料；实际客户端另记 |

必备场景：中文及空格路径、品牌空值、动态表头和长备注；非法参数／路径／动作；跨账号越界；计划篡改、重复 apply、并发编辑、偏好和分区变化；写入发生但响应丢失、重启恢复；不支持的原生表格明确停止；多进程 BUSY；慢请求期间主协议可响应；无随机候选、旧缓存、正文指令注入；日志隐私。

验证分为：合成协议测试、现有 CLI 回归、独立安装、实际客户端、单独授权的飞书测试文档闭环。分别报告，不以合成成功冒充平台成功。

历史工作区 EPERM 如实记录；字节一致临时副本通过不能称原工作区问题已修复。正式 0.10.0 曾有 106 项通过，不能将旧数量当本轮证据。

## 9. 完成定义

- 首版契约、授权原型和故障用例通过，旧 CLI 无回归。
- 实际 Codex 完成工具发现、查询、预览、授权执行和结果核验。无真实试点授权时明确待平台验收。
- 单条直存和首次创建确认分别验收；跨客户端能力只按实测表述。
- Windows 包能独立启动，退出与未知结果恢复有证据，安装和授权说明可操作。
- SPEC、REQ/PROG、待验证清单和 Skill 反映实际结果；记录残留限制。
- 不预定版本号；版本提升、全局安装、GitHub 推送、Tag/Release 按后续授权执行。
