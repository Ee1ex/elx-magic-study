## 1. 实施顺序与共同约束

建议依次执行：OPT-01 防重复整理 → OPT-02 计划生命周期与恢复 → OPT-03 同步断点 → OPT-04 图谱摘要。各项是独立可验收切片，不攒成一次大重构。

开始实施前：

1. 用户确认要做哪些切片及顺序。以下涉及持久化字段的建议需确认语义，不能仅凭任务编号自动迁移真实状态。
2. 读 AGENTS、状态、SPEC 和相关实现，重新跑基线；保留用户及其他工具的修改。
3. 为当前问题补失败用例，先看到预期失败，再做最小修改。
4. 先使用合成资料和旧状态夹具，真实状态仅作获授权的只读诊断。真正回填或修复个人资料需单独的范围与恢复方案。
5. 相关验收通过后同步 SPEC、台账、待验证记录并作本地提交。发布、安装副本升级和远端写入另按当次授权处理。

共同不做：新数据库、向量服务、全库重写、自动删除、权限扩大、实际定时任务创建、多平台适配。没有足够证据时不改变成功判定来“消除报错”。

## 2. OPT-01 防止重复整理生成笔记

**关联**：BUG-001。目标：只处理新输入或内容实际变化的来源，不反复整理自己刚生成的笔记。

**输入**：已完成写入计划的合成样本；旧版 documents 中 source／document 类型混用的夹具；maintenance 当前筛选条件。

**当前原因**：输入来源通过 processedHash 记录完成，但输出来源笔记同样属于 source，仍可能满足 pending 条件。单靠页面标题或出现 ELX记录 字样判断角色不可靠。

**确认实施的方案（以下保留原任务卡）**：

- 在新记录上明确区分输入资料与生成知识页，命名可用 `recordRole`，具体值和落点实施前确认。
- 完成标记绑定实际输入版本。只增加知识页链接或操作标记，不应被解释成原始资料有新内容。
- 新生成来源笔记不会因其 kind=source 自动进入输入队列；用户明确要求重整时仍可生成新计划。
- 旧记录没有角色时保持兼容，列为可解释的待分类状态；不得一律标已处理，也不得自动重写所有正文。
- 若可通过已完成计划与来源 URL 唯一恢复关系，先生成本地迁移预览；不能唯一对应的留给用户判断。

**影响范围**：library-core 的 capture/source-content/finishPlan/sync/maintenance，角色数据契约，相关流程参考和测试。查询、图谱继续可读取旧记录，不依赖所有用户一次迁移完成。

**不变项**：飞书权限、远端正文写入策略、账号隔离、源快照保留。

**验收**：

1. 输入 A 完成整理生成 B；连续维护两次，A/B 均不作为新输入重复入队。
2. A 的正文改变后只产生一项该版本待办；不因 B 的导航追加触发整库重整。
3. 新来源 C 正常入队；只有链接时如实标待获取正文。
4. 旧版夹具能读取，未知角色不被静默丢弃；相同版本计划不重复生成。

**停止条件**：无法区分用户原文和输出，或需要改写旧记录的历史语义。先报告样本和选项，不全量回填。

**交付**：失败／通过测试、最小代码改动、数据兼容说明、SPEC 与 Bug 状态更新。

## 3. OPT-02 计划生命周期与恢复诊断

**关联**：REQ-006、ISSUE-004、ISSUE-005。目标：旧预览不冒充待办；写入不明时能看清差异并安全恢复。

**输入**：未执行预览、被新方案替代的预览、部分完成批次、模拟“服务端 success 但内容校验失败”记录。

**确认实施的方案（以下保留原任务卡）**：

- 给未执行计划增加取消／被替代的明确终态；保留 payload、digest 和历史，不删操作文件。
- apply 对终态明确拒绝。替代关系指向新计划，但新计划的授权摘要不能沿用旧值。
- unknown／sending 不能通过“取消”假装远端没发生；必须先只读核对实际目标。
- status/plans 输出“完成、待确认、待查证、已替代”的简明摘要，区别业务完成与进程退出码。
- 失败诊断保留必要的预期／实际片段差异和失败类别，不把全文、密钥或账号详情写进普通日志。
- ISSUE-004 先核对实际正文与变换规则，才能判断是写入问题还是纯格式差异。不能未经证据扩大 normalizeText 或忽略警告。
- 若增加归一化，测试必须证明：允许的格式变化可通过，而真实文字丢失、重复或错误仍失败。

**影响范围**：library-core 计划状态与 recover、library 命令入口及 plans 展示、maintenance 草稿去重、writes 参考、操作状态夹具。

**不变项**：不新增自动重发写入，不自动回滚删除，不把 success 当作内容核验成功。

**验收**：

1. 取消或已替代计划无法 apply；仍可追溯原内容与新计划。
2. 成功写入但响应丢失，recover 只读确认，写请求计数不增加。
3. 一批中已确认步骤跳过，剩余步骤只有在基线与授权仍匹配时继续。
4. 真实内容缺失继续阻断；纯格式差异有明确、有限的接受规则。
5. 定时维护不重复提示已失效预览；unknown 仍显示为需要处理。

**停止条件**：远端结果无法确定、权限变化、恢复需要删除／覆盖，或必须扩大旧计划授权。保留状态并提交具体方案。

**交付**：生命周期说明、恢复案例及测试、相关用户提示、当前已知问题状态。真实失败记录的修复不自动包含在代码验收中。

## 4. OPT-03 目录断点与真正的增量刷新

**关联**：BUG-002。目标：资料超过单次扫描预算时，下一次从剩余位置继续，并且不误判旧资料离开范围。

**输入**：多页目录、多层 Wiki、超过 maxNodes 的夹具，以及扫描中断和绑定变化场景。

**确认实施的方案（以下保留原任务卡）**：

- 持久化一次目录扫描的待遍历节点、当前分页位置与已处理范围；与账号、读取根及扫描批次绑定。
- 区分“枚举到哪里”和“哪些正文已刷新”。现有 syncCursor 只解决后者，不复用一个数字假装两者都完成。
- 到预算即保存进度；恢复后既不会反复从第一页开始，也不会跳过上一页未处理的节点。
- 只有确认完整枚举后才能判断旧条目是否离开范围；保留缓存记录而非删除。
- 节点移动、读取根变化、账号变化或游标失效时明确重建必要范围，不能继续错误上下文的扫描。
- 版本／修改时间可靠时可以跳过未变正文；缺可靠元数据时保留明确的刷新策略，不声称零请求。

**影响范围**：lark 列表元数据、enumerate/sync、扫描状态、status 与 maintenance 覆盖提示、测试和数据兼容文档。

**不变项**：只读取已授权范围，不扩大到全租户，不删除缓存或远端文档。

**验收**：

1. 三页、多层目录且单次预算小，连续运行最终遍历完全部唯一文档。
2. 在页中断点退出后恢复，没有遗漏、重复入库或重复判定完成。
3. 未扫描完成时，未见到的旧条目不被标 outOfScope；完整扫描后才更新范围标记。
4. 账号或读取根变化时拒绝沿用旧检查点。
5. 同一正文版本不反复下载／重整的行为有明确计数证据；没有可靠版本时准确报告降级。

**停止条件**：目录变化无法稳定识别、需要改变授权范围、或扫描状态需要不可逆迁移。先形成方案，不绕过范围检查。

**交付**：可复现断点测试、最小游标数据协议、覆盖统计及恢复说明。

## 5. OPT-04 让真实图谱获得有用摘要

**关联**：BUG-003。目标：点击真实节点能知道“讲什么、何时有用、依据在哪”，且摘要不会比正文悄悄落后。

**输入**：无 summary 的旧版记录、带元信息和操作标记的正文、Agent 新整理的知识页、更新后的文档版本。

**确认实施的方案（以下保留原任务卡）**：

- Agent 整理时提供短简述，保存在索引，并记录对应正文版本。不要仅在演示夹具里填写摘要。
- 对旧文档先考虑提取一段干净正文，明确标为“正文摘录”；不得把截取文本称为 AI 综合摘要。
- 过滤标题、来源元信息、ELX记录 标识等无助理解的内容；没有合适段落就如实显示缺失。
- 正文变更时使旧摘要失效或标记旧版本；下次整理再更新，不强制全库模型调用。
- 图谱使用有效简述／摘录，保留原文和读取时间。无需新增图数据库或向量模型。

**影响范围**：整理输出协议、finishPlan/sync 的摘要保存、retrieval 的节点投影、graph.html 侧栏和搜索、模板、测试。

**验收**：

1. 真实格式的合成知识页进入图谱后有可解释的短说明，不再全部显示无摘要。
2. 页面正文更新后不把旧摘要当最新；新旧版本关系可检查。
3. 输入中的 HTML／脚本、链接等作为文本安全展示。
4. 缺失摘要不影响原文访问；图谱点击、筛选、邻居聚焦在窄屏和桌面可用。

**停止条件**：必须接入额外付费模型、把私人正文发给新服务或全量改写已有知识。先说明成本、范围与替代方案。

**交付**：摘要协议、旧记录兼容说明、真实结构夹具、浏览器证据与 SPEC 更新。
