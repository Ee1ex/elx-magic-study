# 书屋工作台

> 查看书屋状态、确认整理方案、处理尚未入库的资料。

所属知识库：实际知识库名称

最近更新：实际时间与本次读取范围

索引覆盖：本轮目录／正文读取实际完成情况

## 📚 书屋现在怎么样

| 指标 | 当前情况 | 去哪里处理 |
|---|---|---|
| 已归档知识笔记 | 按知识库索引统计资料整理／主题综述／实践记录 | 内容主题目录 |
| 待确认变更 | 当前有效预览数量 | 下方增改预览／多维表格待确认视图 |
| 异常待处理 | 缺正文、登录失败或明确失败的事项数量 | 多维表格异常待处理视图 |
| 写入待查证 | 已发送但结果未核实数量 | 先核对已有结果，不能直接再导入 |

统计不含工作台、偏好、管理页，不把索引未覆盖的资料当已统计。单次已完成事项数量不等于整库笔记总数。

## 📝 这次准备怎么改

| 事项 | 目标 | 变更前 | 变更后 | 当前状态 |
|---|---|---|---|---|
| 实际预览条目 | 真实分类／标题及链接 | 当前内容或尚未创建 | 新标题、摘要、正文／具体差异 | 待确认／已替代／已完成 |

每项展开保留：来源与读取覆盖、分类理由、标签、实际拟写正文、哪些已有页面会改变。较长正文放对应记录的详细预览或实际预览文档链接。

用户调整意见单独填写，修改意见后由Agent重新生成预览与digest。文档／表格里的状态文字、复选框或意见不是执行授权。

## 🛠️ 哪些资料还没整理进去

| 资料 | 卡在哪里 | 当前情况 | 下一步 |
|---|---|---|---|
| 实际未入库资料 | 材料不足／读取／保存／核验 | 原因与实际覆盖 | 补正文／本人登录／修订预览／查证已有结果 |

明确失败与结果未知分开。已创建但核验未完成不能写成“未保存”，也不能直接重发。已入库但工作台同步失败只补同步工作台。

## 🗂️ 用多维表格查看与筛选

此处放同一张多维表格的总览、待确认、异常待处理、写入待查证和状态看板的真实链接；若飞书文档能原生嵌入视图，则嵌入待办视图，无法嵌入时保留链接，不假装已嵌入。

工作台文档负责短摘要和本次重点，多维表格负责同一份明细的筛选、分组、备注与历史查询。状态与数量来自相同实际数据，不各维护一套手工统计。

## 二、多维表格设计

Base名称：书屋工作台。第一阶段只建一张数据表“待办与变更”，从同一表建立不同视图。没有批次ID、批次进度条或自动批量处理队列；每一行对应实际资料／变更／异常事项。

### 字段

| 字段 | 原生类型 | 由谁维护 | 用途 |
|---|---|---|---|
| 条目名称 | 文本，主字段 | Skill | 资料标题或变更名称；尚无正文时不冒充内容总结 |
| 事项类型 | 单选 | Skill | 新资料入库／已有文档更新／异常资料处理 |
| 状态 | 单选 | Skill | 待确认／待补材料／读取失败／写入待查证／已完成／暂缓 |
| 来源链接 | 超链接 | Skill | 实际来源，不含平台Cookie或凭据 |
| 目标分类 | 文本 | Skill | 核实后的目标路径，未确定则明确留空 |
| 变更前 | 多行文本 | Skill | 当前标题、位置或内容片段，非目标正文不复制改写 |
| 变更后／完整预览 | 多行文本 | Skill | 具体拟写内容或有效预览链接，不只有机器编号 |
| 读取覆盖 | 文本 | Skill | 全文／节选／字幕／部分评论及实际数量 |
| 原因与下一步 | 多行文本 | Skill | 明确缺口／有限错误原因和可执行下一步 |
| 结果文档 | 超链接 | Skill | 核验后的真实结果链接；未知结果标待查证 |
| 最近更新 | 日期时间 | Skill | 实际处理／回读时间，不伪造新鲜度 |
| 我的备注／调整意见 | 多行文本 | 用户 | 用户填写；不覆盖，不变相当作批准按钮 |

来源编号、计划编号、来源版本和记录去重键由实现层维护，需要时作为隐藏技术字段；不让用户填写，也不把它们当成主要预览内容。

### 视图

| 视图 | 类型 | 过滤／分组 | 用途 |
|---|---|---|---|
| 全部事项 | 表格 | 按最近更新排序 | 查明细与有限历史 |
| 待确认变更 | 表格 | 状态＝待确认 | 审阅本次标题、分类与正文差异 |
| 异常待处理 | 表格 | 状态＝待补材料或读取失败 | 看没整理进去的资料及具体原因 |
| 写入待查证 | 表格 | 状态＝写入待查证 | 单独保护可能已创建的资料，避免重复 |
| 状态看板 | 看板 | 按状态分组 | 看事项卡在哪里；不允许拖到已完成就当成实际入库 |

原生表格、看板、筛选与分组能力已对本机官方lark-cli帮助做只读核对；实际资源创建、视图配置和嵌入仍需实施与回读，当前预览不代表真实飞书已配置。

## 三、后续实现约束

- 工作台和Base首次初始化先展示准确对象、用途和自动更新区域。用户同意后，每次资料入库／方案变化／查证结果产生时更新相应记录及文档摘要，不要求另说一句话查看。
- 没有对应事项就不新建记录，不把普通成功入库强制扩成批量流程。以实际来源版本与计划标识去重，已有记录更新原记录，保留历史结果。
- 用户填的备注和偏好保留。机器状态按真实步骤更新；表格中人工改状态不直接执行、取消或掩盖操作。
- 文章成功和工作台／Base同步成功分开；明细同步失败不重建已保存文章。文档与Base存在同步差异时显示实际更新时间／待刷新情况，不声称一致。
- 没有账户／权限／读取证据时停止对应写入，不创建同名副本，不删除旧分类或文件。
- 管理记录不进入普通资料待整理、知识统计或主题召回，避免工作台更新触发自身循环。
- 这次只提供模板预览；没有创建Base、启用自动化、发送消息、修改权限、安装或发布。
