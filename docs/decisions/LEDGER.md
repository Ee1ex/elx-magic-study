## DEC-010 2026-10-03 四项优化实施范围

用户随后明确授权实施已写计划，替代 DEC-009 的本轮文档限制。采用新增可选字段保持旧状态可读；未知角色不自动回填。所有运行测试使用合成状态；真实资料迁移、全局安装升级和发布仍需独立范围确认。

## DEC-011 内容分类由当前 Agent 判断，脚本核对

2026-10-03：沿用四个大书架，最多再分一层主题位置；一份新资料只创建一篇主笔记，跨领域用标签和引用。分类候选不是事实，语义判断交给已读正文的 Agent，不新增模型服务。新字段进入现有不可变计划与 digest，修改分类重建预览。只有链接留待整理，未知旧角色不批量推断；不自动创建目录、搬家或改写关联主题。

## DEC-012 原生图标以网页可见结果为准

当前未找到确认可用的公开图标写接口，因此使用宿主浏览器原生选择器，不改名加Emoji、不调用私有接口。状态脚本只检查目标与正文并保存宿主回执。已有未知图标视为人工选择保护；普通导航变更保持稳定主题。真实试点发现添加图标可能先写随机值，需记录前态与刷新核对。

## DEC-013 项目内 OpenCLI SDK 适配

2026-10-04：使用公开导出的 Page SDK，不注册或修补全局OpenCLI适配器。飞书选择器使用open Shadow DOM，普通target resolver不能可靠处理；只读DOM定位后通过SDK原生输入操作，不调用页面私有API。缺浏览器时记录未知而非空图标。写前日志、刷新取证和只读恢复保持；终端可用不等于无浏览器。

## DEC-014 图标成为可选宿主流程

2026-10-04：核心知识整理不依赖界面自动化。只有新建分类或分类名变化且当前会话有真实可调用界面工具时询问；同批合并确认，普通正文变化不触发。客户端与网页能力分别核对，已有图标默认保护。实验脚本继续归档，不新增依赖或状态机。

## DEC-015 介绍／偏好与启用状态分开

2026-10-04：onboarding.json位于个人状态目录，未绑定可用。记录介绍和明确意向，不记录聊天／凭据，不替代真实工具和任务状态。later采取不主动重问的保守策略，当前用户主动指令优先；每轮最多一个相关可选提示，无后台监听。

## DEC-016 按需分类与不可变依赖计划

2026-10-04：首次空间使用「魔法书屋知识库」，旧绑定不改名；空间创建由 Agent 按官方 CLI 确认／回读，不增加第二套远端写入器。分类通过 shelf 和前序 parentStep 纳入已有计划机制，预览仅用步骤号，执行才解析真实父节点，保持 payload/digest 不变。新分类最多两层，先复用，未知写入保留恢复边界。OpenCLI 缺失优先桌面应用引导，CLI、Agent Skills、浏览器桥接分别核验。
