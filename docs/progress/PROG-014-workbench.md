# REQ-019 实施与现有知识库试点

日期：2026-10-12；LEVEL 1。正式发布与安装仍0.8.0，本轮源码未发布、未升级安装。

## 得到的功能

- 一篇工作台合并书屋状态、增改预览和异常未入库事项，配套一张Base“待办与变更”；五个视图为全部事项、待确认、异常、待查证和按状态看板。没有批次ID、批量队列或进度条。
- capture/source-content、plan、apply结果及未知写入、recover和未发送计划终止后同步管理记录。主文章完成与管理同步完成分别报告；重复apply只补同步管理信息。
- 用户填写偏好列和调整意见可直接在飞书编辑；每次调用读取，偏好变化询问是否先预览旧资料整理。预览带偏好hash，之后发生变化阻断旧方案；旧协议无新增字段保留兼容。
- 主题建议记录来源/目标版本、双方原文和建议，入库后标明待评估，由Agent阅读全文判断；脚本不猜语义，也不直接改主题正文。

## 避免的情况

记录键查重、完整分页和关键字段校验防止误认空表而创建副本；响应未知先查证。只更新机器字段，用户备注不发送回写；文档只替换已绑定自动区域，其他正文保留。自动区域发生人工修改停止更新；已写成功但响应丢失时用区域hash回读恢复。管理页不进入知识统计、普通检索/图谱及维护队列，避免更新自身产生新待办。

管理页仅对恒等自动链接包装、等价时区和表格分隔格式做规范化；实际内容、URL或版本变化不放行。初次只回填最近10份终态计划，活动计划完整保留，已镜像历史保持原记录。

## 合成验证

修改前73项通过。新增前三项先以缺模块失败，再实现；工作区曾完整83项通过。随后补充Markdown资源文字转义和管理失败状态持久化失败隔离，共12项REQ-019专项；最终工作区85项通过，逐文件字节核对一致的系统临时副本85项也通过。覆盖偏好变化、账号/范围阻断、备注保护、管理失败与文章成功分离、未知创建查证、链接转预览历史、外部读取异常、矩阵分页/schema、丢响应后数据变化恢复、元信息资源转义及管理状态本地锁错误不掩盖已核验文章成功。

中间工作区回归再次出现Windows EPERM：一次专项在绑定保存阶段失败，单用例复跑通过；一次84项全量在旧的范围阻断及索引测试的原子rename失败。后续85项完整通过不能认定环境根因已解决。未修改store或系统配置、未删除残留文件；工具输出与最后工作区日志、副本字节清单在忽略产物中保留。

## 真实试点证据

用户批准使用现有库；通过项目源码、本人用户身份执行，不依赖全局旧安装。实际配置3篇管理页、1个Base及首表13字段、5个目标视图，放入既有书屋管理目录，首页仅追加导航。

飞书首表的默认表格视图保留；5个自定义工作视图之外没有删除原有用户资源。

- 工作台及Base初始同步28条明细；首页导航计划完成后29条。连续回读/同步仍29条，无重复记录或无变化文档写入。
- 2项历史待确认、3项历史写入待查证仍按原始记录显示；没有将历史失败改成完成，也没有重新导入对应文章。所有原操作文件字节摘要保持。
- 表格人工区和文档备注均保留；Base更新读回存在短延迟，首次立即读取仍空，后续实际读取确认备注存在，再核对连续同步保护。
- 偏好表用户填写列实际为空，未代填；默认说明没有被当成用户选择。真实填写及偏好变更交互由用户后续试用，相关约束已有合成验证。
- 用现有方法资料和知识库搭建主题写入1条有双方原文的补充建议；主题正文保持。没有新建测试知识文章，真实验收不冒充“新文章全链路已测”。
- 三个筛选条件、看板按状态分组、视图URL、Base归属及文档正文均经官方CLI回读。文档提供真实视图链接，未声称原生嵌入。

私人ID、链接、正文、创建日志、回执和前后快照仅在忽略的artifacts/workbench-live与个人状态目录，不进入提交。

## 剩余边界
