# PROG-007 可选宿主界面图标引导

日期：2026-10-04。REQ-013用户要求：检测Agent有没有Computer Use能力，新增分类或分类名变化时询问图标优化，再用客户端／网页操控。

## 实现

新增references/optional-icons.md并连接SKILL、capture、classification和maintenance。真实能力依据当前可调用工具及最小只读验证，不依据品牌。新增／改名必须先获得独立授权且实际成功；同一批图标建议合并询问，用户同意才操作。保护已有人工图标，观察不清不当无图标；无能力跳过、定时任务不自动写入。

不新增代码、依赖、图标命令或个人状态，不恢复experiments脚本。保留真实“添加图标可能先写随机值”的经验作为停止／回读边界。当前正式版本仍为0.4.0，本次指引未发布未安装。

## 指引场景核对（文档走查，不是Agent端到端测试）

| 场景 | 规则结果 |
|---|---|
| 有浏览器控制工具且新建分类成功 | 展示目标、图标和理由，询问后操作 |
| 品牌为Codex但当前工具不可用 | 无能力，跳过；不能推定支持 |
| 只有截图能力，不能点击 | 不算可执行 |
| 有客户端控制，网页工具缺失 | 只读确认客户端目标后可走客户端流程 |
| 普通笔记新建或分类正文补充 | 不触发 |
| 分类改名仅在计划中，尚未执行 | 不提前改图标 |
| 已有自定义图标 | 默认保留；替换需具体确认 |
| 用户拒绝／暂缓 | 不操作，同批不再问 |
| 未登录或权限不足 | 等用户处理或跳过，不改权限 |
| 定时无人值守 | 留建议，不改图标 |
| 点击后结果不明 | 只读核对实际状态，不盲目重复 |

文档规则可复用不代表Kimi Code、Claude Code或飞书客户端已验证；按实际会话能力判断。没有为文案变更添加镜像实现的测试或重复运行无关业务测试。
